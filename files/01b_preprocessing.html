1 Purpose of this stage

This notebook runs after Stage 1 (data preparation) and before Stage 2 (EDA). It is the dedicated preprocessing pass — missing-value imputation, categorical encoding, and numeric normalization — as its own auditable stage, rather than something implicit inside the modeling code.

Why EDA (Stage 2) still reads the pre-imputation data, not this stage’s output: EDA’s job is to honestly characterize the raw data, including its missingness (e.g. the ~35% product-join gap documented in Stage 1). Imputing before EDA would hide exactly the pattern that analysis is supposed to surface. So the dependency graph is:

Stage 1 (data prep) ──┬──> Stage 1.5 (this notebook: preprocessing) ──> Stage 3 (modeling)
                       └──> Stage 2 (EDA, reads pre-imputation data)

Everything here is fit only on model_train and applied unchanged to validation, crc_calibration, iid_holdout, and official_future_test — the same train/calibration/test separation rule Stage 1 already established for the price cap and category medians.

5 Cleaning blank strings before anything else

Some categorical columns in the released data contain empty strings ("") rather than NA for missing values. Left alone, a sufficiently common "" would pass the min_category_count bar in the encoding step below and get treated as a legitimate category — a silent bug, not caught by any check downstream, since "" still !is.na(). It’s cleaned up front, once, so every later step (missingness counts, encoding, normalization) sees the same, correctly-blank-aware data. This is deliberately generic across every entry in CATEGORICAL_FEATURES – shippingCountry, productType, and age_band alike – rather than a one-off fix for whichever column happened to trigger an error first.

clean_categorical <- function(x) {

7 Fitting the preprocessor on model_train

Three things are fit here, all from model_train only:

  1. Imputation values — the median of each numeric feature.
  2. Encoding scheme — for each categorical feature, the set of levels with at least min_category_count rows; anything rarer (or unseen later) is recoded to "OTHER".
  3. Normalization parameters — mean and standard deviation of each numeric feature, for z-score scaling, computed after median imputation is applied to model_train (not on the raw, still-missing data). Fitting order matters here: imputing first adds a spike of values exactly at the median, which shifts the mean and shrinks the SD slightly relative to the raw, incomplete column. If normalization parameters were estimated on the raw column instead, the frozen mean/SD would be a small mismatch with the data every split actually gets normalized against post-imputation, and the resulting _z columns would land at mean ≈ -0.01 / SD ≈ 0.97 instead of the intended mean 0 / SD 1 — mathematically harmless in most cases, but not the clean, defensible normalization the project wants to lock in before Stage 3. The original (unscaled) columns are kept too, since the current baseline (logistic regression) doesn’t require scaled inputs — but distance-based or regularized models added later will, so the scaled columns are computed once, here, rather than ad hoc per model.

MIN_CATEGORY_COUNT <- 30

fit_preprocessor <- function(dt, min_category_count = MIN_CATEGORY_COUNT) {
  medians <- sapply(NUMERIC_FEATURES, function(col) median(dt[[col]], na.rm = TRUE))

  # Normalization parameters are fit on model_train AFTER imputation, not
  # before -- see the prose above. This uses a local imputed copy purely for
  # computing mean/SD; the actual imputation applied to every split still
  # happens in apply_preprocessor() below, driven by the frozen `medians`.
  imputed_for_norm <- copy(dt)
  for (col in NUMERIC_FEATURES) {
    set(imputed_for_norm, which(is.na(imputed_for_norm[[col]])), col, medians[[col]])
  }

  norm_params <- rbindlist(lapply(NUMERIC_FEATURES, function(col) {
    vals <- imputed_for_norm[[col]]
    data.table(feature = col, mean = mean(vals), sd = sd(vals))
  }))
  setkey(norm_params, feature)

  # A zero (or undefined) SD would turn (x - mean) / sd into Inf/NaN for
  # every row of that feature -- a silent corruption, not an error, unless
  # it's caught explicitly here. Fail fast instead.
  degenerate <- norm_params[sd == 0 | is.na(sd)]
  if (nrow(degenerate) > 0) {
    stop(paste(
      "fit_preprocessor: degenerate (zero or NA) SD for feature(s):",
      paste(degenerate$feature, collapse = ", ")
    ))
  }

  allowed_levels <- lapply(CATEGORICAL_FEATURES, function(col) {
    counts <- dt[!is.na(get(col)), .N, by = col]
    setnames(counts, col, "level")
    counts[N >= min_category_count, level]
  })
  names(allowed_levels) <- CATEGORICAL_FEATURES

  # Binary imputation values (mode on model_train, non-missing rows only).
  # This was the missing piece that let isMale/premier NAs pass straight
  # through apply_preprocessor() unimputed (they were only ever cast with
  # as.integer(), which leaves NA as NA). Fitting a mode here, the same way
  # medians are fit for numeric features, closes that gap.
  binary_modes <- sapply(BINARY_FEATURES, function(col) {
    x <- dt[[col]]
    x <- x[!is.na(x)]
    if (length(x) == 0) {
      stop(paste("fit_preprocessor: no non-missing values available to compute a mode for", col))
    }
    as.integer(names(sort(table(x), decreasing = TRUE))[1])
  })

  list(
    medians = medians,
    binary_modes = binary_modes,
    norm_params = norm_params,
    allowed_levels = allowed_levels,
    min_category_count = min_category_count,
    fitted_on_n = nrow(dt)
  )
}

8 Applying the preprocessor to every split

Code 
apply_preprocessor <- function(dt, preproc) {
  dt <- copy(dt)
  
  # 1. Missing-value imputation (numeric)
  for (col in names(preproc$medians)) {
    if (col %in% names(dt)) {
      med <- preproc$medians[[col]]
      set(dt, which(is.na(dt[[col]])), col, med)
    }
  }
  
  # 2. Encoding (categorical)
  for (col in names(preproc$allowed_levels)) {
    if (col %in% names(dt)) {
      allowed <- preproc$allowed_levels[[col]]
      current <- dt[[col]]
      
      recoded <- fifelse(
        is.na(current) | !(current %in% allowed),
        "OTHER",
        current
      )
      
      set(
        dt,
        j = col,
        value = factor(
          recoded,
          levels = union(allowed, "OTHER")
        )
      )
    }
  }
  
  # 3. Normalization
  for (col in preproc$norm_params$feature) {
    mu <- preproc$norm_params[feature == col, mean]
    sigma <- preproc$norm_params[feature == col, sd]
    
    z_col <- paste0(col, "_z")
    
    if (col %in% names(dt) && sigma > 0) {
      set(
        dt,
        j = z_col,
        value = (dt[[col]] - mu) / sigma
      )
    }
  }
  
  # 4. Binary variables -- impute NAs with the fitted mode, THEN cast.
  # (Casting alone -- as.integer(NA) -- does not impute anything; it leaves
  # NA as NA. This was the actual bug: isMale/premier NAs were silently
  # passing all the way through to Stage 3.)
  for (col in names(preproc$binary_modes)) {
    if (col %in% names(dt)) {
      mode_value <- preproc$binary_modes[[col]]
      set(dt, which(is.na(dt[[col]])), col, mode_value)
      set(dt, j = col, value = as.integer(dt[[col]]))
    }
  }

  # customer_missing / product_missing are join-outcome flags created
  # upstream in Stage 1. They are never imputed -- a missing "was this join
  # missing" indicator would be a modeling error, not a legitimate gap to
  # fill -- but they are cast to a clean integer type for consistency with
  # the other binary predictors Stage 3 uses.
  for (col in MISSINGNESS_FLAGS) {
    if (col %in% names(dt)) {
      set(dt, j = col, value = as.integer(dt[[col]]))
    }
  }
  
  dt
}

# Fitting the preprocessor on `model_train`

Three things are fit here, all from `model_train` only:

1.  **Imputation values** — the median of each numeric feature.
2.  **Encoding scheme** — for each categorical feature, the set of levels with at least `min_category_count` rows; anything rarer (or unseen later) is recoded to `"OTHER"`.
3.  **Normalization parameters** — mean and standard deviation of each numeric feature, for z-score scaling, computed **after** median imputation is applied to `model_train` (not on the raw, still-missing data). Fitting order matters here: imputing first adds a spike of values exactly at the median, which shifts the mean and shrinks the SD slightly relative to the raw, incomplete column. If normalization parameters were estimated on the raw column instead, the frozen mean/SD would be a small mismatch with the data every split actually gets normalized against post-imputation, and the resulting `_z` columns would land at mean ≈ -0.01 / SD ≈ 0.97 instead of the intended mean 0 / SD 1 — mathematically harmless in most cases, but not the clean, defensible normalization the project wants to lock in before Stage 3. The original (unscaled) columns are kept too, since the current baseline (logistic regression) doesn't require scaled inputs — but distance-based or regularized models added later will, so the scaled columns are computed once, here, rather than ad hoc per model.

```{r fit-preprocessor}
MIN_CATEGORY_COUNT <- 30

fit_preprocessor <- function(dt, min_category_count = MIN_CATEGORY_COUNT) {
  medians <- sapply(NUMERIC_FEATURES, function(col) median(dt[[col]], na.rm = TRUE))

  # Normalization parameters are fit on model_train AFTER imputation, not
  # before -- see the prose above. This uses a local imputed copy purely for
  # computing mean/SD; the actual imputation applied to every split still
  # happens in apply_preprocessor() below, driven by the frozen `medians`.
  imputed_for_norm <- copy(dt)
  for (col in NUMERIC_FEATURES) {
    set(imputed_for_norm, which(is.na(imputed_for_norm[[col]])), col, medians[[col]])
  }

  norm_params <- rbindlist(lapply(NUMERIC_FEATURES, function(col) {
    vals <- imputed_for_norm[[col]]
    data.table(feature = col, mean = mean(vals), sd = sd(vals))
  }))
  setkey(norm_params, feature)

  # A zero (or undefined) SD would turn (x - mean) / sd into Inf/NaN for
  # every row of that feature -- a silent corruption, not an error, unless
  # it's caught explicitly here. Fail fast instead.
  degenerate <- norm_params[sd == 0 | is.na(sd)]
  if (nrow(degenerate) > 0) {
    stop(paste(
      "fit_preprocessor: degenerate (zero or NA) SD for feature(s):",
      paste(degenerate$feature, collapse = ", ")
    ))
  }

  allowed_levels <- lapply(CATEGORICAL_FEATURES, function(col) {
    counts <- dt[!is.na(get(col)), .N, by = col]
    setnames(counts, col, "level")
    counts[N >= min_category_count, level]
  })
  names(allowed_levels) <- CATEGORICAL_FEATURES

  # Binary imputation values (mode on model_train, non-missing rows only).
  # This was the missing piece that let isMale/premier NAs pass straight
  # through apply_preprocessor() unimputed (they were only ever cast with
  # as.integer(), which leaves NA as NA). Fitting a mode here, the same way
  # medians are fit for numeric features, closes that gap.
  binary_modes <- sapply(BINARY_FEATURES, function(col) {
    x <- dt[[col]]
    x <- x[!is.na(x)]
    if (length(x) == 0) {
      stop(paste("fit_preprocessor: no non-missing values available to compute a mode for", col))
    }
    as.integer(names(sort(table(x), decreasing = TRUE))[1])
  })

  list(
    medians = medians,
    binary_modes = binary_modes,
    norm_params = norm_params,
    allowed_levels = allowed_levels,
    min_category_count = min_category_count,
    fitted_on_n = nrow(dt)
  )
}
```

# Applying the preprocessor to every split

```{r apply-preprocessor}
apply_preprocessor <- function(dt, preproc) {
  dt <- copy(dt)
  
  # 1. Missing-value imputation (numeric)
  for (col in names(preproc$medians)) {
    if (col %in% names(dt)) {
      med <- preproc$medians[[col]]
      set(dt, which(is.na(dt[[col]])), col, med)
    }
  }
  
  # 2. Encoding (categorical)
  for (col in names(preproc$allowed_levels)) {
    if (col %in% names(dt)) {
      allowed <- preproc$allowed_levels[[col]]
      current <- dt[[col]]
      
      recoded <- fifelse(
        is.na(current) | !(current %in% allowed),
        "OTHER",
        current
      )
      
      set(
        dt,
        j = col,
        value = factor(
          recoded,
          levels = union(allowed, "OTHER")
        )
      )
    }
  }
  
  # 3. Normalization
  for (col in preproc$norm_params$feature) {
    mu <- preproc$norm_params[feature == col, mean]
    sigma <- preproc$norm_params[feature == col, sd]
    
    z_col <- paste0(col, "_z")
    
    if (col %in% names(dt) && sigma > 0) {
      set(
        dt,
        j = z_col,
        value = (dt[[col]] - mu) / sigma
      )
    }
  }
  
  # 4. Binary variables -- impute NAs with the fitted mode, THEN cast.
  # (Casting alone -- as.integer(NA) -- does not impute anything; it leaves
  # NA as NA. This was the actual bug: isMale/premier NAs were silently
  # passing all the way through to Stage 3.)
  for (col in names(preproc$binary_modes)) {
    if (col %in% names(dt)) {
      mode_value <- preproc$binary_modes[[col]]
      set(dt, which(is.na(dt[[col]])), col, mode_value)
      set(dt, j = col, value = as.integer(dt[[col]]))
    }
  }

  # customer_missing / product_missing are join-outcome flags created
  # upstream in Stage 1. They are never imputed -- a missing "was this join
  # missing" indicator would be a modeling error, not a legitimate gap to
  # fill -- but they are cast to a clean integer type for consistency with
  # the other binary predictors Stage 3 uses.
  for (col in MISSINGNESS_FLAGS) {
    if (col %in% names(dt)) {
      set(dt, j = col, value = as.integer(dt[[col]]))
    }
  }
  
  dt
}
```

# Preprocessing quality gate — data validity (before writing anything)

Everything above does the work; this section proves it, deliberately *before* any file is written. Each check below is independent and specific — a passed run means every failure mode it checks for (dropped rows, leftover `NA`s, blank-string categories masquerading as a real level, mismatched factor levels across splits, target leakage, `Inf` values) is confirmed absent, not just assumed absent because no error was thrown earlier. Checking cross-split compatibility here, ahead of `fwrite()`, means a bad run never gets the chance to leave a stale or inconsistent `*_prep.csv.gz` on disk for Stage 3 to pick up.

## 1b. Row identity is preserved (not just row counts)

Matching row *counts* before/after is necessary but not sufficient: `apply_preprocessor()` never reorders or joins, but this check confirms that directly, since CRC and the future-period drift audit implicitly depend on each split's rows keeping a stable identity. There is no single event ID in the released data, so `customer_id` + `variant_id` (in original row order) is the strongest identity check available here -- it is not guaranteed unique per event (see Stage 1's repeated-triplet finding), but an *order or content* change in either key would still be caught.

```{r gate-1b-row-identity}
identity_pairs <- list(
  model_train = list(before = model_train_dt, after = model_train_prep),
  validation = list(before = validation_dt, after = validation_prep),
  crc_calibration = list(before = crc_calibration_dt, after = crc_calibration_prep),
  iid_holdout = list(before = iid_holdout_dt, after = iid_holdout_prep),
  future_test = list(before = future_test_dt, after = future_test_prep)
)

for (nm in names(identity_pairs)) {
  before_dt <- identity_pairs[[nm]]$before
  after_dt <- identity_pairs[[nm]]$after

  same_customer <- identical(before_dt$customer_id, after_dt$customer_id)
  same_variant <- identical(before_dt$variant_id, after_dt$variant_id)

  if (!same_customer || !same_variant) {
    fail_check(paste(nm, "row identity (customer_id/variant_id, in order) changed during preprocessing."))
  } else {
    pass_check(paste(nm, "row identity preserved (customer_id/variant_id unchanged, same order)."))
  }
}
```
