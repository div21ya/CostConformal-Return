1 Purpose of this stage

This notebook is Stage 5 of the pipeline and covers Phase 2’s database-connectivity requirement: it moves Stage 4’s five *_features.csv.gz splits into a real relational database (SQLite, via DBI/RSQLite) and retrieves data back out using SQL, in R.

Database choice, stated explicitly: SQLite rather than MySQL/PostgreSQL/MongoDB. It is file-based, needs no server process, and the DBI interface used here (dbConnect, dbWriteTable, dbGetQuery, dbExecute) is nearly identical across backends — swapping the driver in dbConnect() for RMariaDB::MariaDB() or RPostgres::Postgres() would port this notebook to a client-server DB with almost no other change, if that’s ever required.

This is not a disconnected checkbox stage: load_split_from_db(), defined here, is the function Stage 6’s model zoo actually calls to retrieve training data — so the database is a real part of the pipeline from here on, not a side demo that gets ignored afterward.

A useful side effect, worth noting given Stage 4’s RAM constraints: the three retrieval queries below (row counts, return rate, category group-by) run their aggregation inside SQLite, and only the small aggregated result ever enters R. None of them loads a full table into memory — on a 6 GB machine, this is a genuine advantage of querying a database over fread()-ing a whole file just to compute a summary statistic from it.

7 Retrieval function for Stage 6: load_split_from_db()

Stage 6’s model zoo retrieves training data through this function rather than reading the *_features.csv.gz files directly – this is the actual “data retrieval using R” deliverable, not just the one-off demo queries above. Factor levels (frozen back in Stage 1.5/Stage 4) are restored on the way out, the same way restore_factor_types() did for the CSV round-trip.

Code 
load_split_from_db <- function(con, split_name, preprocessor, feature_selector, bin_levels) {
  dt <- as.data.table(dbGetQuery(con, paste0("SELECT * FROM ", split_name)))

  for (col in feature_selector$categorical_features) {
    if (col %in% names(dt)) {
      levs <- union(preprocessor$allowed_levels[[col]], "OTHER")
      set(dt, j = col, value = factor(dt[[col]], levels = levs))
    }
  }
  for (col in names(bin_levels)) {
    if (col %in% names(dt)) {
      set(dt, j = col, value = factor(dt[[col]], levels = bin_levels[[col]]))
    }
  }
  dt
}

# Retrieval function for Stage 6: `load_split_from_db()`

Stage 6's model zoo retrieves training data through this function rather than reading the `*_features.csv.gz` files directly -- this is the actual "data retrieval using R" deliverable, not just the one-off demo queries above. Factor levels (frozen back in Stage 1.5/Stage 4) are restored on the way out, the same way `restore_factor_types()` did for the CSV round-trip.

```{r retrieval-function}
load_split_from_db <- function(con, split_name, preprocessor, feature_selector, bin_levels) {
  dt <- as.data.table(dbGetQuery(con, paste0("SELECT * FROM ", split_name)))

  for (col in feature_selector$categorical_features) {
    if (col %in% names(dt)) {
      levs <- union(preprocessor$allowed_levels[[col]], "OTHER")
      set(dt, j = col, value = factor(dt[[col]], levels = levs))
    }
  }
  for (col in names(bin_levels)) {
    if (col %in% names(dt)) {
      set(dt, j = col, value = factor(dt[[col]], levels = bin_levels[[col]]))
    }
  }
  dt
}
```
